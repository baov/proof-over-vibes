# AGENTS.md

## Harness

This project has a deterministic enforcement layer generated by the `codebase-harness` skill. Agents must comply with these rules.

### Executable invariants

The architecture rules (ADR-0001) and the shape thresholds are made executable by scripts in `tools/harness/`. Full list and statuses in [docs/technical/invariants.md](docs/technical/invariants.md).

- Before any commit, run: `npm run harness` (same as `bash tools/harness/run_all.sh`). All invariants are in `warn` for now: exit 2 means warnings, exit 1 means errors.
- Each check's message includes the remediation to apply; read it before looking elsewhere.
- To understand an invariant without checking it: `node tools/harness/check_layers.mjs --explain` (also `check_shape`, `check_test_coverage`).
- To test the checks themselves: `npm run harness:selftest`.
- Sensitive zones (a human reviews before merge) are listed in `docs/technical/invariants.md`, section "Sensitive zones".

### Test-case bridge to real tests

Every scenario under `docs/business/test-cases/` carries YAML front-matter pointing to its automated test. `tools/harness/check_test_coverage.mjs` checks the consistency.

- Adding a test-case: fill in the front-matter (`automated_test` as `<path>::<test name>`, or `status: pending`).
- Adding a test: check it has a matching test-case, otherwise create one.

### Mutation testing

Tests written without line-by-line human review are kept in check by mutation testing. A green test is not proof: only a killed mutant is.

- Scope and threshold: INV-010 in [docs/technical/invariants.md](docs/technical/invariants.md).
- Run locally: `npm run mutation` (critical scope) or `npm run mutation:diff` (changed files only).
- A surviving mutant is dealt with by adding a test that expresses the unprotected **behavior**, never a test written to kill the mutant. If the mutant matches no behavior that counts, exclude it explicitly in `stryker.config.mjs` with a comment justifying it.
- Never lower a threshold to get CI passing.
